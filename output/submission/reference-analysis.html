사용자가 판단할 수 있게 만든다.

현재 쇼케이스 49개 항목·5페이지를 브라우저로 훑고, 관련성이 높은 출품작과 수상작 총 10개의 상세 페이지를 확인했다. 공개된 데모 3개도 접속해 초기 화면을 확인했다. TRACE에는 판단에서 원문으로 이동하는 화면, 기준별 사건 대조, 불확실성과 후속 확인, 분석가 검토를 전면에 두는 방향을 적용한다.

아래의 “배울 점”은 제출 설명과 공개 화면에 대한 설계 평가다. 경쟁 서비스의 모든 백엔드 기능·성능·현장 적합성을 독립 검증한 결과는 아니다. 수상 사실과 서비스의 주장·우리의 평가를 구분한다.

수상 사실은 무엇으로 확인했나

Korea Times, 2026-07-12는 BONE, DoS, ANGAE, DELPHI, SEASIDE, Nyx와 Supporty·Kestrel의 특별상을 보도했다. 전자신문, 2026-07-10은 8개 팀 수상과 Supporty·Kestrel의 오리건 연계 추천을 전했다. KAIST 항공우주공학과, 2026-09-21는 SEASIDE의 2026-07-05 T4 수상을 별도로 발표했다.

대회는 7월 3–5일 개최됐고, 보도일과 대학 발표일은 다르다. 언론 기사가 주최 측 발표를 재전달했을 수 있어 기사 수를 독립 성능 검증 횟수로 세지 않는다. 당시 보도된 47개 솔루션과 현재 쇼케이스의 49개 표시 항목은 서로 다른 시점·집계이며 동일한 숫자로 바꾸지 않았다.

수상작에서 배울 점

작품·확인 수준좋은 구성TRACE에 적용
DELPHI
T3 수상 · 배지+보도		판단과 관측 사이의 증거 체인을 설명하고, 시나리오 순서와 정보의 기여를 시각화한다. 공개 데모의 초기 화면에서 구현된 동창리 시나리오와 미구현 시나리오의 구분을 확인했다.결론 → 기준 → 사건 → 인용 → 원출처의 경로를 문서와 그래프에서 탐색하도록 한다. 비교 서비스의 확률 숫자를 복제하지 않고 가능성과 근거 신뢰도를 구분한다. 설명에 등장하는 “환각 원천 차단” 등 절대적 성능 주장은 검증된 것으로 인용하지 않는다.
DoS / DOS
T2 수상 · 배지+보도		범위를 한 가지 판단에 좁힌다. 유출 신호의 존재와 공개 노출 여부를 분리해, 조사와 판정의 목적이 선명하다.김주애의 공개 등장·육성 징후, 공식 지명·권한, 최종 승계를 다른 명제로 다룬다. 관련 기사를 모으는 것만으로 승계 가능성을 확정하지 않는다.
ANGAE / 안개
T2 수상 · 배지+보도		하나의 문제를 먼저 설명하고 비교 실험과 도입 방식을 제시한다. 공개 데모에도 실험을 이해할 수 있는 화면이 있다. 제출 설명의 수치는 팀의 자체 보고이며 독립 재현하지 않았다.기능 수보다 실제 실행의 증거를 보여준다. 최신 실행 23개 원문·19개 유효 인용·18분 43초와 검증 테스트를 기록한다. 근거 없이 처리 시간을 줄였다는 비교 효과를 주장하지 않는다.
SEASIDE
T4 수상 · 배지+보도+KAIST		여러 센서·공개 정보를 지휘관의 관심 구역과 후속 활동으로 연결한다. 제출 설명에서 공개 저장소의 데이터 범위도 밝힌다.기준별 다음 확인·반증과 정보 공백을 보고서에 연결한다. 항적·위성 등의 범위와 접근 실패를 명시하고, 김주애 질의와 무관한 지도를 강제로 넣지 않는다.
Nyx
T5 수상 · 배지+보도		사용자와 구체적인 상황, 불확실할 때 재확인으로 전환하는 동작을 설명한다. 시제품 사진·착용 사진·영상이 있어 형태가 전달된다.공식 지명 미확인을 지명 부재로 바꾸지 않는다. 근거가 부족하면 판단을 유보하고 반증과 후속 확인을 표시한다. 영상은 실제 UI 조작과 사례를 보여준다.

관련성이 높은 일반 출품작

작품본받을 점적용 결과
ATLAS LENS임무 질문에서 판단, 통제 조건, 후속 조치로 이어지는 구조. 제품 화면과 한 문장 가치 제안이 일치한다.핵심 판단을 앞에 두고 기준별 대조와 다음 확인으로 연결한다. 제출 첫 화면도 보고서 결과를 보여준다.
Rabbi / rabbion공개 교범의 문단과 citation을 지식 구조로 보존하고, 그 지식이 사용되는 사례를 함께 제시한다.기준 원문·판본·해시의 불변 보존, FTS5 조항 검색, 자료별 재확인 정책을 설명한다. TRACE의 실제 타입 관계·JSON-LD를 보여주며 MCP·SPARQL·OWL 기능이 있다고 확대하지 않는다.
Holocron분석가가 주도하는 탐색, 원문 하이라이트, 결과에서 다음 검색으로 이어지는 검토 동선.주석과 기준 원문을 누르면 정확한 인용 구절·번역·원출처를 확인한다. 원출처 검토와 승인 이력은 본문과 분리된 도구로 둔다.
Open Intelligence Layer / 오일이수집 대상, 데이터 소스, 실제 화면과 영상을 함께 제시한다. 공개 데모에서 지도·항적 화면과, 대회 이후 DB·수집기를 내려 일부 레이어가 비어 있다는 안내를 확인했다.스크린샷 8장과 설명 영상을 질문 → 실제 수집 기록 → 보고서 → 기준 → 원문 → 이미지 → 관계 → 전망 → 검토의 흐름으로 구성한다. 데이터 유형은 계획에 포함하되 실제 미연결 피드는 구분한다.
혜안 / Agentryx AI핵심 아이디어를 구체적인 작동 방식으로 설명하고, AI의 출력이 최종 판단권자를 보조함을 드러낸다.AI 초안과 분석가의 승인 상태를 분리한다. 근거 변경 후 재검증과 승인 해제를 제출 설명·시연에 포함한다.

운영 상태를 직접 확인하며 얻은 교훈

오일이 공개 데모는 대회 이후 라이브 DB·수집기가 종료돼 일부 레이어가 비어 있다는 안내를 보여준다. DELPHI 공개 데모는 초기 시나리오 화면에서 구현 범위와 미구현 항목을 구분한다. 이는 데모의 보존과 실제 실행 범위를 명확히 표시해야 한다는 교훈이다. TRACE는 보존한 실제 결과를 서버 계정 없이 탐색하는 웹과, 실제 수집을 실행하는 로컬 앱을 구분해 제공한다.

이번 제출에 반영한 보완

  1. 출처와 신뢰도가 연결된 문서 지면을 첫 스크린샷으로 사용한다. 주석 창·기준 표·이미지·전망·관계·실제 수집 기록·입력 화면을 8장으로 구성한다.
  2. 약 3분의 한국어 설명 영상으로 하나의 김주애 질문을 끝까지 따라간다. 실제 수집 기록과 보존 보고서 탐색, 각 실행의 자료 수와 소요 시간을 구분한다.
  3. 관계 그래프의 지나친 간격과 축소된 글자 문제를 발견해 배치와 화면상 글자 크기를 보완한다.
  4. 심사자가 로그인 없이 보존 결과를 탐색하는 웹 데모와, 새 질문을 실제 수집하는 로컬 앱을 함께 제공한다. 온라인에서 실시간 분석을 하는 것처럼 표시하지 않는다.
  5. 저장소·데모·영상·스크린샷과 설명을 연결해, 제출 설명의 주요 기능을 심사자가 직접 확인할 수 있게 한다.

다음 평가 실험

성능 개선을 측정하려면 동일한 질문·자료 기간·접근 조건에서 수작업 분석과 TRACE를 비교해야 한다. 시간, 유효 인용률, 실제 독립 원출처 수, 핵심 지표 확보율, 분석가의 수정·유보 빈도를 기록한다. 아직 이런 비교 실험을 수행하지 않았으므로 “몇 배 빠르다” 같은 생산성 효과는 제출에 넣지 않는다.
